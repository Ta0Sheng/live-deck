# 架构与取舍

> 这份文档回答三个问题：进程怎么分、数据怎么流、为什么这么设计。

## 1. 进程模型

```
live-deck app
└── host.py                    ← 窗口宿主（可选，无 pywebview 时退化为浏览器）
    └── deck/server.py          ← 唯一常驻服务，持有 aiohttp + WebSocket
        ├── asr/sensevoice.py   ← 字幕子进程（拉流 → Demucs → SenseVoice）
        └── fish/engine.py      ← 直播鱼子进程（读字幕/弹幕 → LLM → 草稿）
```

三条边界：

1. **服务端不做推理。** 字幕和鱼都是独立进程，模型崩溃不会拖垮界面。
2. **子进程可以被杀。** 服务端持有 `Popen` 句柄，关房间/关窗口时连同孙子进程一起清理。
3. **状态走文件。** 模式（草稿/公开）是 `data/state/mode.txt`，字幕是 `data/logs/asr-live-<room>.log`，
   鱼读这两个文件。好处是每个进程都能单独重启，坏处是要处理「文件正在写」——所以写入用追加 + 读取容错。

### 为什么鱼不放在服务端进程里

鱼的决策循环里有大量 `await`（模型调用、等待、抽帧），和 WebSocket 广播抢同一个事件循环会让界面卡顿。
独立进程还有个副作用：改鱼的人格/代码只需要重启鱼，不用重启整个窗口。

### 单实例

- 窗口宿主：`8765` 已经在听就直接开窗口，不再拉第二套服务。
- 服务端：端口占用时打印一行日志后退出，不抛异常。
- 鱼 / 字幕：启动时扫 `psutil` 进程表，同房间已有实例就退出（防上次的孤儿叠进程）。

## 2. 数据流

### 2.1 弹幕

```
B站 WebSocket ──► LiveDanmaku ──► Hub.push({t:"danmaku"}) ──► 界面
                        │
                        ├──► data/danmaku/<room>.jsonl   （学说话习惯、问题范本）
                        └──► 鱼的缓冲（最近 40 条）
```

- 自己发的弹幕（`bot_uid`）会被跳过，否则鱼的「鱼，」会被自己叫醒。
- `鱼，` 开头算点名（只认逗号，不认冒号）；「。」开头是使用者的示范句，只学不回。
- 弹幕里出现「搜 XXX」只有 `owner_uid` 能触发，避免观众让鱼乱查。

### 2.2 字幕（双路）

```
FLV ──► PyAV ──► 4s 切片 ──► Demucs(htdemucs) ──► SenseVoice(int8, 实时)
                                                    │
                                                    └──► 精修：回看 36s + fp32，每 30s 一次
                                                              │
                                                              └──► DeepSeek 同音字纠错（可选）
```

- **实时句**：4 秒切片、能量切句、int8 模型。延迟约 8 秒，先保证「跟得上」。
- **精修句**：把最近 36 秒人声重新喂给 fp32 模型，切句后带 `#clean` 前缀输出。服务端把它们写进
  `asr-live-<room>.log` 给鱼读，并把实时句标成「原文」。
- **同音纠错**：只允许改错字、补标点；输出长度翻倍或带解释的一律丢弃，保留原文。

一个踩过的坑：PyAV 对打包音频给的是 `(1, 2n)` 的交错采样，不是 `(2, n)`。当双声道喂给 Demucs，
音频会被拉成两倍长，字幕直接变念经。`sensevoice.py` 里显式 reshape 成 `(-1, 2).T`。

### 2.3 画面

```
playurl API ──► ffmpeg 抽 1 帧 ──► JPEG 字节（stdout，不落盘）──► 多模态模型 ──► 一句描述
```

- 抽帧走 `image2pipe`，不写临时文件；这台机器的 Python 曾经没有写权限，这个习惯保留了下来。
- 画面描述每 60 秒一条，只保留最近 3 条；鱼发言时如果画面超过 45 秒会重抓。
- 下播时不抽帧：否则每分钟一条「拿不到流地址」，还会白打 B站 接口。

### 2.4 鱼的决策循环

```text
每 10 秒醒一次
├── 重读模式文件（live / draft）
├── 每 5 分钟重读样本（界面 ✔/✘ 写进去的）
├── 每 90 秒确认房间还在播；连续两次不在播 → 下班
├── 配额：每小时条数、总条数、随机「懒得说」
├── 冷场检测：120 秒没弹幕也没字幕 → 给一个主动开口的机会
├── 组装上下文：字幕尾 8 行 + 弹幕尾 8 条 + 画面上次描述 + 冷场/点名提示
├── 调用模型 → SKIP 或一句话
├── 硬过滤：复述、去重、敏感词、长度
├── [查:词] → B站 搜索 → 摘要进知识库，这条不发
├── 像人度打分（另一个 prompt，1–5）
└── < veto → 丢弃；否则随机延迟后发（或只打草稿）
```

关键点：**打分发生在发送之前**，且打分器只看「这一刻的语境 + 这一句」，不看历史。
这样同一句话在不同场面的分数可以完全不同，符合「场面不对，再妙的话也不像人」。

### 2.5 样本检索与评测

旧实现只把样本文件的最后 24 好 / 12 坏塞进 prompt，等于「只记得最近」。现在每次发言前：

```
当前语境（字幕尾 + 弹幕尾 + 画面描述）
   │  字符二元组相似度（containment 70% + dice 30%，不依赖分词）
   ├─► 最像的 8 条好样本 / 4 条坏样本
   └─► 再补最近 4 条（保证刚点的 ✔/✘ 立刻生效）
```

相似检索让旧经验回来，最近兜底防「新反馈被相似度淹没」。`fish.retrieval=false` 可退回旧行为，
用来做 A/B。评测（`live-deck eval`）则用固定场面 + 固定评分尺子，把「有没有变好」变成可比较的数字。

## 3. 延迟预算

| 环节 | 典型耗时 | 备注 |
|---|---|---|
| 拉流 + 4 秒切片 | 4.0 s | 切片越长上下文越稳，延迟越高 |
| Demucs（4s 窗，GPU） | ≈ 0.5 s | 7.4× 实时；CPU 约 2.2 s |
| SenseVoice int8 | ≈ 0.3–1 s | 8 线程 |
| 网络/缓冲 | ≈ 1–2 s | B站 流本身的缓冲 |
| **合计** | **≈ 8 s** | 从主播说完到字幕出现 |

鱼发弹幕前还有 3–8 秒随机等待（扣掉 GPU 带来的额外延迟 `delay_comp`），让它看起来不像条件反射。

## 4. 失败处理

| 故障 | 行为 |
|---|---|
| 弹幕 WebSocket 断 | 5 秒后重连，状态点变灰，界面自动恢复 |
| 字幕子进程退出 | 4 秒后重启；一分钟内反复退出则指数退避，封顶 60 秒 |
| 房间没开播 | 字幕和鱼都暂停拉起，每 4→60 秒探一次；不会整夜空转 |
| 模型调用失败 | 这一轮跳过，不写样本，下一轮继续 |
| 端口被占 | 打印一行日志并退出（视为「已经开着一个」） |
| 关窗口 | `taskkill /T` 杀整棵树；避免孤儿鱼/字幕 |
| 磁盘写失败 | 只影响日志/样本，不阻塞主循环 |

## 5. 取舍

**为什么用文件而不是数据库？** 所有状态都是「读最后 N 行」，文件足够；用户可以直接用记事本改样本，
不需要装数据库，也不需要迁移。

**为什么不用流式 ASR 做精修？** 精修要的是准，不是快；SenseVoice 是非流式模型，回看 36 秒的准确率
明显高于流式 zipformer。快的那一路已经由 v1/实时通道兜底。

**为什么把「像人度」交给另一个模型？** 让生成器自评容易自我合理化；换一个只看语境的 prompt，
相当于一个独立评审。代价是每条多一次短请求。

**为什么默认沉默？** 直播间里最惹人烦的不是说错话，是每句都接。默认沉默 + 阈值可调，
把「活跃度」变成一个显式参数，而不是靠 prompt 里写「少说点」。

## 6. 扩展点

- 换平台：实现 `bili.py` 里的 `resolve_room / play_url / is_live / wallet`，服务端不用动。
- 换模型：`fish.model` 指向任何 OpenAI 兼容的 chat completions 端点（需要小改 `ask_model` 的 URL）。
- 换人格：只改 `persona/persona.md`。
- 加一条流：在 `deck/server.py` 里加一个 `_xxx_loop`，往 `Hub` 推事件，界面加一列。
