# 人格、样本与调参

## 1. 一条分界线

| | 人格（persona） | 记忆（memory / data） |
|---|---|---|
| 是什么 | 它是谁、怎么说话、什么不做 | 它经历过什么 |
| 存在哪 | `persona/`，**进仓库** | `data/`、`fish.memory`，**gitignore** |
| 新电脑上 | 原样保留 | 空的 |
| 谁改 | 你手写 | 运行时自己长出来 / 界面按钮写 |

所以「换个角色」和「清空记忆」是两件独立的事：改人格不动数据，删 `data/` 不丢人格。

## 2. 人格文件

`persona/persona.md` 是一段 Markdown，**原样**作为 system prompt 发给模型。文件顶部的
HTML 注释会在加载时去掉，适合写「这段为什么这么改」。

一个可用的人格至少要说清四件事：

1. **身份**：它是谁、在哪个场景里（观众、房管、路人……），不要让它演设定。
2. **判断标准**：什么算「像人」，什么算「一眼机器人」。
3. **输出契约**：长度、语气、不能说的词、`SKIP` 表示不说。
4. **动作语法**：本项目里是 `[查:词]`（去查资料）和 `投喂 礼物 xN`（演练投喂）。

不要写：账号、房间号、真实姓名、API key。人格文件会被发到模型服务商。

## 3. 运行时上下文怎么拼

`ask_model()` 按固定顺序拼 system prompt：

```
persona.md                        ← 永远在第一段
＋ Neuro 台词样本（可选，persona/corpus/tone.md）
＋ 这间房的说话习惯（平均句长、问句比例、笑声比例）
＋ 使用者示范句（弹幕以「。」开头的）
＋ 长期记忆（fish.memory，可选，截断 1200 字）
＋ 被夸过的发言（data/samples/good.md）
＋ 被扣分的发言（data/samples/bad.md）
＋ 语境合适 / 语境不对（data/samples/context-*.md）
＋ 观众问句范本（从本房间弹幕里抽）
＋ 刚查到的资料（180 秒内有效）
＋ 最近问过的问题 / 问得太多的提醒
＋ 知识库（这间房问明白过的词）
```

这些块都是**可选的**：文件不存在就跳过。新电脑上只有第一段，所以第一句话可能更「素」——
跑一段时间、点几次 ✔/✘ 之后才逐渐贴合这间房。

样本块不是固定取「最近 N 条」：每次发言前，用当前语境和每条样本的【场面】做字符二元组相似度，取最像的 8 条好样本、4 条坏样本，再补最近 4 条兜底。这样旧经验不会被新样本挤掉，你刚点的反馈又一定进得去。`fish.retrieval=false` 可以退回旧的「最近 N 条」行为，用来做 A/B。

## 4. 两条学习轴

界面上的三个按钮对应三条写入路径：

| 按钮 | 含义 | 写到哪 |
|---|---|---|
| ✔ | 语境合适 + 说得像人 | `good.md` **和** `context-good.md` |
| ✘人 | 说话方式不像人（机器味、端着、太正式） | `bad.md` |
| ✘景 | 这个场面不该开口（话本身可能没问题） | `context-bad.md` |

为什么负例要分两轴：如果「不该开口」的样本混进「不像人」里，模型会学到「少说话 = 像人」，
最后变成哑巴；反过来，「像人」的样本混进语境轴，会让它在不合适的场面也硬接。

运行时每 5 分钟重读这些文件，不用重启。

## 5. 调参

| 想要 | 调什么 | 方向 |
|---|---|---|
| 更安静 | `fish.veto` ↑（3.3 → 4.0） | 分数不够就不发 |
| 更活跃 | `fish.veto` ↓、`fish.min_gap` ↓ | 但别低于 45 秒 |
| 更少冷场硬找话 | 冷场阈值在 `engine.py`（120 秒） | 改代码，不是配置 |
| 更短 | `fish.max_tokens` ↓、人格里改「20 字以内」 | 两者要一致 |
| 更保守 | `fish.temperature` ↓ | 0.5–0.7 |
| 不查梗 | 人格里删掉 `[查:词]` 那段 | 代码仍支持，但模型不会用 |
| 换称呼 | `fish.name` / `fish.call_word` / `fish.addresses` | 人格里同步改 |

`fish.veto` 的经验值：3.0 已经明显话少，3.3 是「偶尔插一句」，4.0 接近「只在被点名时说」。
分数是 1–5，打分器自己也会波动，别把它当精确刻度。

## 6. 写人格的几个建议

- **写否定比写肯定有用。** 「不要总结/不要复述/不要每句都接」比「要自然」可执行得多。
- **给一个可观察的标准。** 「20 字以内、一句为主」比「简短一点」好。
- **留一个退出键。** 明确告诉它可以输出 `SKIP`，否则它会为了完成对话而硬说。
- **别让它演设定。** 「蓝发鲸鱼娘只是外形，别演人设」这类句子能显著减少 cosplay 腔。
- **一次只改一处。** 人格、样本、阈值同时动，出了问题不知道是谁的锅。

## 7. 安全边界

- 人格文件只是文本，不能执行代码、不能读文件。模型输出会经过敏感词、复述、去重过滤，
  但**不能保证**它永远不说错话——这是 LLM 的固有风险。
- 弹幕内容是外部输入，可能包含「忽略以上指令」之类的注入。人格里不要写「无条件服从弹幕」，
  代码层也不把弹幕当指令执行（只有 `owner_uid` 的「搜 XXX」会触发搜索）。
- 发送和花钱各有独立总闸，默认关闭；改之前先想清楚。

## 8. 评测：怎么知道它有没有变好

```bash
live-deck eval make --n 40    # 固定场面（从 data/logs，或 --logs 指旧项目日志）
live-deck eval run            # 逐条生成、盲评 1–5；--auto 用评审器
live-deck eval report         # 比较最近几次的均分 / 跳过 / 长度
```

改人格、改样本、改检索、换模型之后各跑一次，看均分是涨是跌。没有这步，所有「更像人了」都只是印象。
