# 常见问题

### 为什么字幕延迟 8 秒？

v2 字幕是「4 秒切片 → 人声分离 → 非流式识别」：切片本身就要等 4 秒，GPU 分离约 0.5 秒，
识别 0.3–1 秒，加上 B站 流缓冲，合计约 8 秒。想要更快就用 `streaming` 引擎（2–3 秒），
代价是错字明显增多。

### 为什么有两条字幕（绿色那条是什么）？

绿色带「精」字的是精修通道：回看最近 36 秒音频、用 fp32 模型重识别，每 30 秒出一段。
它比实时句准，但慢；只写给直播鱼读，不挡界面。鼠标悬停能看到实时识别的原文。

### 为什么窗口宿主非要 Python 3.12？

不是非要。`pywebview` 依赖 `pythonnet`，后者对新版 Python 的支持滞后；3.13/3.14 上可能装不上。
装不上不影响使用：`live-deck app` 会自动退回浏览器。服务端本身 3.11+ 都能跑。

### 鱼发了弹幕，但别人看不到？

大概率是账号**没有实名**。B站 对未实名账号的弹幕是静默丢弃的：接口返回成功、带弹幕 id，
但其他观众看不到。先用手动发一条验证；礼物不受此限制（但会真扣钱）。

### 会封号吗？会花钱吗？

- 默认不发弹幕、不送礼，只读。
- 打开 `send_danmaku` 后，行为和你在网页上手动发弹幕一样，但频率由程序控制；
  自动化操作仍可能违反平台协议，风险自负。
- 打开 `allow_gift` 才会花钱，且有每日预算账本（`data/state/gift-ledger.json`）。
  默认「投喂」只是一条文本弹幕。

### 没有 NVIDIA 显卡能跑吗？

能。`pip install -e ".[asr]"`（CPU 版），Demucs 约 1.8× 实时，字幕延迟会到 10–12 秒。
也可以完全关掉人声分离（`asr.separate = false` / `--no-separate`）。

### 没登录、没下模型，能先看界面吗？

可以：`live-deck demo`。它不连 B站、不调模型，四条流都是脚本喂的。
适合第一次 clone 下来确认环境、也适合截图。

### 为什么鱼一直不说话？

按可能性排序：

1. `fish.veto` 太高（默认 3.3，已经偏安静）。
2. 刚开播，字幕/弹幕还没积累，`暂无上下文，继续等`。
3. 模式是「草稿」——草稿也会打印，但只在界面/日志里，不发出去。
4. 模型 key 没配，鱼进程起不来（看 `data/logs/livechat-<room>.out`）。
5. 命中过滤：复述、去重、敏感词、长度。

### 端口 8765 被占用 / 打不开？

先看是不是已经开着一个：`live-deck doctor` 会显示端口状态。关掉旧窗口/进程，或改
`deck.port`。Windows 上 `netstat -ano | findstr 8765` 能找到占用者。

### 改了界面（index.html）不生效？

服务端已经给 HTML 加了 `Cache-Control: no-store`，正常刷新即可。如果还不行，
确认你改的是 `src/live_deck/deck/web/index.html`，并且没有第二个服务实例占着 8765
（只有第一个实例会绑定端口）。

### 改人格要重启吗？

鱼每次启动读一次人格；改完重启鱼即可（关掉窗口再开，或只重启 `live-deck fish`）。
样本文件（`data/samples/*.md`）每 5 分钟自动重读，不用重启。

### 支持抖音/斗鱼/YouTube 吗？

不支持。`bili.py` 里的房间、流地址、弹幕、钱包都是 B站 实现；换平台需要自己实现这一层，
服务端和鱼不用动。

### 为什么不用 Docker？

可以，但收益不大：要挂 WebView2/浏览器、要拿宿主机的 GPU、还要把直播流和音频设备透进去。
这个项目的定位是「本机小工具」，`pip install` + 一个命令更直接。CI 里也不跑需要账号的集成测试。

### 数据会被上传吗？

不会主动上传。只有两类请求出网：B站 的公开接口（房间/弹幕/流/钱包）和 DeepSeek 的
chat completions（人格 + 最近的弹幕/字幕）。日志、样本、知识库都在本地 `data/`。
